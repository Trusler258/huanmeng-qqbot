## 三、踩过的四个坑（都要记住）

### 1. 主题方向搞错（最严重）
模板是**暖色浅底**（`#fdf4ec` → `#f9ece2` → `#f3eff2` 配橙粉光晕），第一版凭印象画成了深紫底
（`(24,20,38)`）。**必须逐项照抄 CSS 里的颜色值，不能凭感觉。**

### 2. RGB 图上画 4 元组 fill 会被忽略 alpha
`ImageDraw` 在 **RGB 模式**图上画 `rounded_rectangle(fill=(150,130,110,23))`，
PIL **直接忽略 alpha** 当实色画。结果页脚药丸成了实心深棕，该区域像素差 **61**。
→ 解法：`_blend_at()` 取样底色做预混合，再传实色。
受影响处：页脚两个药丸、表头分隔线、行分隔线、卡片白边。

### 3. CSS 径向渐变的位置基准不是画布
`radial-gradient(640px 340px at 8% -10%, …)` 里的 `8% -10%` 是**渐变色块内**的中心位置，
色块本身锚定在 `background-origin`（默认 padding-box，即 22,22）。
第一版按「画布 × 百分比」算，光晕跑到卡片中间，左上角应有的橙色完全没有（差 23.9）。
正确公式：
```
中心 = padding 原点 + (size_x × pos_x%, size_y × pos_y%)
glow1 = (22 + 640×0.08, 22 + 340×(-0.10)) = (73.2, -12)
```
按此推算左上角颜色 `(254,214,193)`，Chromium 实测 `(253,213,192)` —— 吻合。

### 4. 字体必须区分 Regular / Bold
第一版 `_resolve_cjk()` 只找「第一个能用的字体文件」，返回的是 `NotoSansCJK-Bold.ttc`，
于是 `bold=False` 的请求也拿到 Bold 文件 —— **全卡文字被加粗**，整体偏重。
→ 解法：`_resolve_font(bold)` 分别维护 Regular / Bold 候选列表。
另外 `td.name` 的 CSS 是 `font-weight:600`，但 Noto CJK 只有 400/700 两档；
实测用 Regular 比 Bold 更贴近 Chromium（平均差 6.28 vs 6.81）。

## 四、其它实现要点

- **行高 44px 不是 36px**：`td.rank` 里的 21px 奖牌（inline-flex）撑高了行盒。
  按 CSS 字面「padding 9×2 + 字号 14」估算是错的，高度会差 68px。
  → 用 Playwright 读 DOM 实测几何（`_probe/_measure_card_geo.py`），别估算。
- **卡片白边 1px 会把内容整体推 1px**：内容起点是 45 不是 44。
- **字体**：中文 `NotoSansCJK-Regular.ttc` / `-Bold.ttc`（ttc 需试 index 并用
  「两个不同汉字位图不同」判定真字形，避免豆腐块）；数字/名次用 `data/web_assets/monocraft.ttf`。
- **图标**：9 个 32×32 PNG 内嵌在模板 base64 里，`extract_icons()` 首次运行时导出到
  `data/web_assets/wdsj_icons/`，之后复用。
- **渐变加速**：numpy 投影求值 + `np.interp`，比逐行画线快几十倍。
- **单数据源**：`modules/commands._daily_rank_payload()` 供 HTML 与 Pillow 共用，
  避免两个渲染路径各拼一份数据导致显示不一致（验证时曾因此得出错误结论）。
